# 2026-11-eu-consumer-rules

Show what a shop owes its customers (seller, legal pages, price notice, price reductions, delivery and payment before ordering, product safety, order button), with every fact taken from Saleor. Read `rules/ui-legal.md` first; it is the destination. `docs/selling-in-the-eu.md` is the merchant's side.

Requires `2026-10-listing-contract`. `upstreamSha` stays empty until the commit that releases this migration exists.

Several defaults change what an existing shop shows. Tell the user about each one marked **Visible** before porting it.

## Steps

1. **Seller and legal pages.** Add `ShopSellerIdentity.graphql`, `src/lib/channels/seller-identity.ts`, `get-seller-identity.ts`, `src/config/legal.ts`, `src/lib/catalog/get-legal-links.ts` and the `imprint` route. The kernel brings the `shop` cache profile.
2. **Footer. Visible.** Replace hard-coded legal links with the imprint link and `getLegalLinks`. An empty `footer` menu renders no columns: a fork that relied on the placeholder Support / Company links has to create the pages and the menu, or keep its own columns.
3. **Price notice.** Add `ChannelPriceDisplay.graphql`, `get-price-display.ts` and `PriceNote`; render it under the product page price (shell and buy box), at the cart totals and in the footer.
4. **Price reductions. Visible on channels that ship to the EU/EEA.** Fetch `pricePrior` / `priceRangePrior` next to the list price. Resolve the reference on the server (`getPriceReductionReference`, `withPriceReference`, the last argument of `toProductCardData`) and make components read `pricing.priceReference`. A fork component that reads `priceUndiscounted` to draw a strike-through must switch. On an EU/EEA channel, products without `priorPrice` lose their sale badge and strike-through: the merchant sets `priorPrice`, or the fork sets `priceReductionReferenceByChannel` in `src/config/pricing.ts`.
5. **Free-shipping threshold. Visible.** The code default is `null` and the value comes from Saleor's shipping methods (`ChannelShippingMethods.graphql`, `free-shipping.ts`, `get-saleor-free-shipping.ts`, wired in `get-storefront-content.ts`). A fork that set its own default in `defaults.ts` keeps it as an override; say so and suggest removing it. The Policies attribute is now "Free shipping threshold override (not recommended)". The old attribute `free-shipping-threshold` is ignored: it was seeded with 75 on every store, so its value is not a merchant's choice. Tell the user that a deliberately set threshold has to be entered again in the renamed field, or better, configured on the shipping method.
6. **Shipping claims. Visible.** Drop the delivery-time sentence from `pdp.attributes.shippingBody`, add `shippingAtCheckout`, and remove the checkout summary's fixed trust tiles.
7. **Order button. Visible.** `checkout.actions.payTotal` reads "Buy now" in English and "Zahlungspflichtig bestellen" in German. Add `OrderLegalNotice`, `CheckoutLegalLinksProvider`, and the links in the checkout session loader. Keep a fork's own button wording only if it still states that ordering costs money.
8. **Product safety. Visible.** Add `src/config/product-safety.ts`, `product.safety` in the mapper and `ProductSafety`. A fork's own PDP template must place the new `slots.productSafety` next to the buy box: the attributes it shows leave the "Product Details" accordion, so a template that skips it would hide them. Map the fork's own attribute slugs in the config.
9. **Returns window. Visible.** `policies.returns.windowDays` is `null` by default. Without a merchant-set window, no returns claim shows. A fork that relied on the 30-day default sets its window in the Storefront — Policies Model.
10. **Billing countries.** A shipped order accepts a billing address from any country (`ShopCountries`, `billingCountries` in the checkout data).
11. **Delivery and payment before ordering. Visible.** Add `ChannelDeliveryPayment.graphql`, `src/lib/delivery-payment.ts`, `get-delivery-payment.ts` and `DeliveryPaymentNote`; render it in the cart drawer and on the cart page. In checkout, add the summary to the session loader (with `paymentMethodsForCheckout` as the fallback), `CheckoutDeliveryPaymentProvider` and `DeliveryPaymentPanel` at the top of the information step. For the postcode check, add the `shippingMethodsForAddress` query and operation, `checkPostcodeDelivery` in `src/app/(checkout)/actions.ts`, `usePostcodeDelivery` with its switch in `src/config/checkout-delivery.ts`, the address fields' `onFieldBlur`, and the information step's field error and submit guard. Replace the shipping step's empty-state sentence with the banners (`noDelivery*` for an excluded postcode, `noMethod*` otherwise, `loadMethodsFailed*` with a retry from `useShippingDeliveries`). A fork whose checkout steps are its own wires the hook and the banner there. Tell the user about the two optional channel metadata keys, `market.deliveryExclusions[.<locale>]` and `payment.methods` (`docs/selling-in-the-eu.md`): without them the note names countries, checkout names only what Paper can charge with, and nothing is said about excluded areas. A store whose shipping methods come from an app gets no early postcode check.
12. Mirror every new message key in all locale files (`legal`, `common.prices`, `common.deliveryPayment`, `checkout.legal`, `checkout.errors.postcodeNotServed`, `checkout.errors.checkingDelivery`, `checkout.shipping.noDelivery*`, `checkout.shipping.noMethod*`, `checkout.shipping.loadMethodsFailed*`, `checkout.shipping.changeAddress`, `checkout.summary.shippingPending`, `pdp.attributes.shippingAtCheckout`, `pdp.safety`).
13. Run `pnpm generate`, `pnpm data:lock`, `pnpm content:export-seed` and `pnpm run verify`.
